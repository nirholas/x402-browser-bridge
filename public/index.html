x402-browser-bridge

Turns any website flow into an x402-paid API — declare a flow in YAML, Puppeteer executes it, and the extracted data, screenshots and step log come back in the response body. Pay in USDC on Base or Solana; the client picks the rail.

Paid with HTTP 402 USDC on Base or Solana Your client picks the rail

⚠️ Terms of service. Automating a website you do not own may breach its terms of service. The bundled flows target demo pages this server hosts itself; a flow marked authorized: false has not been declared as permitted by its author. The operator of a deployment is responsible for the legality of every flow it serves — read the README's terms-of-service section before pointing a flow anywhere else.

Free endpoints

EndpointWhat it does
GET /flowsEvery declared flow with its inputs, extracted fields, price and host allowlist
POST /verifyVerify the HMAC signature on a run record
GET /healthLiveness, payment rails, flow count and browser availability
GET /.well-known/x402x402 discovery manifest

Call it

curl -i -X POST http://localhost:4034/run/{flow} \
  -H 'content-type: application/json' -d '{}'

An unpaid request returns 402 with an accepts array holding both rails, each carrying outputSchema.input / outputSchema.output — everything an agent needs to pay and then call the route correctly.
